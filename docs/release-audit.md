# Diskora release audit — baseline 15 October 2026; updated 16 October 2026

Status: **NOT READY**. This is an audit of the existing Diskwise-branded code in the Diskora repository, not a claim that its Windows binary has run. Findings below describe the **baseline before fixes**; the implementation/verification log at the end is updated as work proceeds. Stable licensing identifiers such as `diskwise-pro` must not be casually renamed.

## Baseline evidence (before edits)

- `npm run test:all`: **pass** — 173 Vitest tests, 31 licence contract tests, TypeScript check, Vite build. Some React `act()` and sourcemap warnings.
- `npm run bench`: **pass** — synthetic JS tree/prune benchmark, Linux x64 / Node 22.22.3, 5 runs per scenario, median 4.39 ms (2k files), 15.20 ms (25k), 111.50 ms (100k), 91.66 ms (120k wide), 1259.14 ms (250k); *not* a disk scan or Rust benchmark.
- `npm audit --omit=dev --audit-level=high`: **0 vulnerabilities** at this time; not a general security guarantee.
- `npm run rust:fmt:check`, `npm run rust:clippy`, `npm run rust:test`: **could not run** (exit 127, `cargo` absent). `npm run fmt:check` and `npm run app:build`: **exit 127**, missing `prettier` and `tauri` executables respectively. No local PostgreSQL, Deno, Supabase, Windows, WebView2, signing certificate, or Dodo credentials.
- Latest main CI at commit `c8a80dd` ([run 38138390040](https://github.com/vaishakh19/diskora/actions/runs/38138390040)): frontend/licence/audit pass, **Rust formatting and PostgreSQL migrations fail**; Windows installer and smoke jobs are skipped. Thus no evidence of a working native build.

## Work log / blockers

Baseline and audit recorded before implementation. A green frontend does not imply a working Windows release.

### Phase 1 — SQL/RPC privilege containment (16 October 2026)

- Repaired `rate_limit_hit` in `0002`: renamed the reserved `window` identifier, qualified the `bucket`/`subject` lookup, used the named primary-key conflict target, and rejected nonpositive limits. Added `0003_restrict_rpc_execute.sql`, revoking `PUBLIC`/client `EXECUTE` on all six `SECURITY DEFINER` RPC signatures and conditionally granting the Supabase `service_role`. Added a CI query checking all six role ACLs against real Postgres.
- **Verified locally in ephemeral PGlite**: all three initial migrations applied after substituting *only* the `pgcrypto` extension statement in `0001`, which PGlite lacks. With `anon`, `authenticated` and `service_role` roles created first, all six functions denied the two client roles and permitted the service role; three calls to `rate_limit_hit` with cap 2 returned `true, true, false`. **Also verified against real PostgreSQL 17 in [CI run 38791605145](https://github.com/vaishakh19/diskora/actions/runs/38791605145):** migrations, device-limit and six RPC ACL checks passed. No deployed Supabase project was tested.

### Phase 2 — scanner, transport and cleanup guardrails (16 October 2026)

- Scanner work-stack tracks active workers, signals completion before joins, wakes waiters on cancellation, rejects link-follow requests, skips Windows reparse points, and records entry/depth caps as partial. Added deadline-based empty/fanout/queue-cancel tests and Unix link test. Corrected the native progress event shape to match the shared contract and guarded invalid-root aggregation. **Rust tests have not run here** (Cargo unavailable); Windows/NTFS correctness is unverified.
- Native cleanup now requires a complete in-memory scan, a server-generated finding with an exact eligible file path, canonical approved root and non-linked parents, an unchanged size/mtime and a one-use two-minute preview token plus explicit confirmation; it never recurses into directories. `dryRun` cannot mutate, the browser demo refuses execution, and permanent deletion is **disabled** in the Tauri command/UI pending Windows handle-level race tests. Recycle Bin moves remain unverified on Windows. A same-size, same-mtime content rewrite and a path swap between validation and action remain open risks, so **P0-2 is not closed**.
- Packaged Tauri origins with no injected native bridge now display a startup error rather than selecting synthetic data. A Windows packaged startup test is still required. Fixed several apparent Rust type/constructor errors, but native compilation has **not** been demonstrated.
- **Verified locally**: `npm run test:all` passed (179 Vitest tests, 31 licence contract tests, TypeScript check and Vite build); `git diff --check` passed. The 2026-09-22 WASM build of actual rustfmt formatted Rust sources. In [Windows CI run 38791605145](https://github.com/vaishakh19/diskora/actions/runs/38791605145), **`cargo fmt --check` passed but Clippy failed**; native tests, debug build, installer and smoke steps were skipped. Local Cargo remains unavailable, and Windows compilation/safety are not verified. A CI change now attempts to annotate the Clippy log tail; that annotation path has not yet been validated (the first attempt matched no compiler diagnostics). `@tauri-apps/cli` and Prettier are pinned; `npm run fmt:check` still fails on pre-existing formatting across 51 frontend files and is **not** reported as passing.

### Phase 3 — contain unsafe live fulfilment (16 October 2026)

- Discovered that live checkout could take money while `dodo-webhook` generated an **opaque random key** rather than a signed device payload, stored only its hash and never delivered it. The code now refuses any non-test checkout (503) and any live/unknown-environment `payment.succeeded` before claiming or acknowledging the webhook; the unsafe licence-issuing path was removed. Test payments may be recorded, but **no licences are issued**. These guards prevent accidental live enablement; they do not implement paid fulfilment.
- Added `0004_webhook_retry_claims.sql` with body-bound claims, per-attempt token, five-minute stale-worker lease, separate `processed`/`in-flight`/`mismatch` states, and idempotent revocation rows. The Edge handler now processes and records completion **before** 2xx, returns 503 on partial failure and refuses unknown-order/malformed revocations rather than silently claiming them done. Refund/provider payloads and DB multi-write atomicity remain unverified and require real integration tests.
- **Verified locally in PGlite**: migrations `0001`–`0004` applied with the `pgcrypto` extension statement substituted; both new RPCs deny `anon` and permit `service_role`; claim/in-flight/retry/finish/mismatch/stale-token assertions passed. **Also verified against real PostgreSQL 17** in [CI run 38793800761](https://github.com/vaishakh19/diskora/actions/runs/38793800761): all four migrations, eight RPC permissions, device-limit/RLS checks, and ordered webhook retry assertions passed. No deployed Supabase/Dodo integration was run. Edge TypeScript parsed/transpiled with esbuild; no Edge deployment, payment or delivery test has run. CI's dependency audit now fails on high-severity issues rather than silently continuing, and the Windows link-only job was renamed so it cannot be mistaken for a real NTFS scan.

### Phase 4 — accurate sale UX and release documentation (16 October 2026)

- Replaced the licensing screen's invented monthly/subscription prices with the configured ₹1,499 one-time **not-for-sale** price. Purchase control is disabled, missing scheduled scans/exports are labelled unimplemented, the free tier no longer appears to lack basic duplicate previews, and the sidebar links to the page. Updated README, licensing, testing and installer guides to state which behaviors are planned and which actually passed checks; removed CI's fake “Windows smoke scan” claim.
- **Verified locally** after the UI edits: `npm run test:all` passed (179 frontend tests in 11 files, 31 licence tests, TypeScript checks, Vite build); the App test asserts the unavailable purchase control is disabled. Subsequently disabled release source maps in `vite.config.ts`: `npm run build` passed with no `.map` artifacts and no Tailwind sourcemap warning. `git diff --check` passed. Non-fatal React `act(...)` test-environment warnings remain. Release CSP and Windows bundling are still open.
