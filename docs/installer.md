# Windows installers

Diskwise ships two installers, both configured in `src-tauri/tauri.conf.json`:

```json
"bundle": {
  "targets": ["msi", "nsis"],
  "windows": {
    "webviewInstallMode": { "type": "downloadBootstrapper" },
    "nsis": { "installMode": "currentUser", "languages": ["English"] }
  }
}
```

- **MSI** — the machine-wide, Group-Policy-friendly package. Standard Add/Remove Programs entry.
- **NSIS** — the per-user installer, smaller and faster, with the same uninstall entry.

## Prerequisites

| Tool | Version | Notes |
| --- | --- | --- |
| Node.js | ≥ 20.19 | `npm install` first |
| Rust (stable) | ≥ 1.77 | `rustup default stable` |
| Microsoft C++ Build Tools | current | required by the `bundled` SQLite feature |
| WebView2 runtime | any | the NSIS bootstrapper downloads it if absent |

On Windows:

```powershell
winget install OpenJS.NodeJS.LTS
winget install Rustlang.Rustup
winget install Microsoft.VisualStudio.2022.BuildTools --override "--quiet --add Microsoft.VisualStudio.Workload.VCTools"
```

## Building

```powershell
npm install
npm run build          # typecheck + vite build -> dist/
npm run app:build      # cargo build --release + bundle MSI and NSIS
```

Or the underlying commands, if you want to see each step:

```powershell
npx tauri build                        # default: both targets
npx tauri build --bundles msi          # MSI only
npx tauri build --bundles nsis         # NSIS only
npx tauri build --debug                # faster, unoptimised, for local testing
```

Artefacts land in:

```
src-tauri/target/release/bundle/msi/Diskwise_0.1.0_x64_en-US.msi
src-tauri/target/release/bundle/nsis/Diskwise_0.1.0_x64-setup.exe
```

## Application identity

| Field | Value |
| --- | --- |
| Product name | Diskwise |
| Identifier | `com.diskwise.app` |
| Version | 0.1.0 |
| Publisher | Diskwise |
| Category | Utility |
| Window | 1280×820, minimum 960×640, resizable, undecorated with a custom title bar |
| Icon | generated by `npm run icons` (32/128/256 PNG, `.ico`, `.icns`, Store logos) |

`npm run app_version` in the running app returns the same version, identifier, platform and
architecture the installer wrote, so the About information can never drift from the package.

## Code signing

**Diskwise installers are not code-signed.** This is deliberate and stated plainly:

- No certificate, no private key and no signing credential exists anywhere in this repository, the
  frontend bundle, or the packaged application.
- Nothing in the app claims to be signed, and the UI never displays a "verified publisher" state it
  cannot back up.
- Windows SmartScreen will therefore warn on first run. That is the honest consequence of shipping
  unsigned, and it is better than pretending otherwise.

Signing is a **separate release task** with its own key custody. When it happens it belongs in a
release-only workflow, roughly:

```powershell
# Example shape only — the real command depends on the certificate provider.
signtool sign /fd SHA256 /tr http://timestamp.digicert.com /td SHA256 `
  /sha <cert-thumbprint> src-tauri\target\release\bundle\msi\Diskwise_0.1.0_x64_en-US.msi
```

Guidance for whoever does it:

1. Keep the certificate in an HSM or a secret manager. Never in the repo, never in CI logs.
2. Sign both the installer **and** the bundled `.exe`.
3. Timestamp the signature so it stays valid after the certificate expires.
4. Record the thumbprint and the signing date in the release notes, so users can verify
   independently.

## Uninstall

Both installers register a standard uninstall entry:

- MSI: Apps & features → Diskwise → Uninstall.
- NSIS: the same entry, plus `uninstall.exe` in the install directory.

Uninstalling removes the application files. It does **not** remove the local database
(`%APPDATA%\com.diskwise.app\diskwise.sqlite3`), which holds the user's preferences and cached scan
history. That is intentional: a reinstall should not lose settings. Deleting that file is the
documented way to start from a clean slate.

## High-DPI

The window is resizable from 960×640 and all three regions scroll independently, which is what makes
the layout hold at 100, 125 and 150% display scaling. The icon set includes the sizes Windows asks
for at each scale. There is no manifest DPI override; the app follows the system setting.
